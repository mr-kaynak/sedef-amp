# Captures: Neural Amp Modeler files

Source: `engine/include/sedef/dsp/capture/`, `engine/src/dsp/capture/`, `cmake/SedefNam.cmake`,
`plugin/src/CaptureLibrary.*`, `ui/src/features/amp/CapturePanel.tsx`. Tests:
`engine/tests/capture/` (`[capture]`, `[untrusted]`), `plugin/tests/CaptureLibraryTests.cpp`,
`ui/src/features/amp/capture.test.tsx`.

## 1. What it models

A capture is a neural network trained on a real amp (or a pedal into an amp, or a whole miked
rig) with the open-source [Neural Amp Modeler](https://github.com/sdatkinson/neural-amp-modeler)
trainer. The `.nam` file is JSON: an architecture, its config, a flat list of weights, the sample
rate the model runs at, and optional metadata (name, gear, who captured it, the interface levels
used while capturing).

Sedef plays a capture in place of the amp section. The pedals stay in front of it; the cab,
EQ and effects stay after it. For a full-rig capture (the cab and mic are already in the model)
Sedef's cab can be skipped.

The networks are run by [NeuralAmpModelerCore](https://github.com/sdatkinson/NeuralAmpModelerCore)
0.6.0 (MIT), fetched by CPM with a pinned SHA-256 together with its dependencies, Eigen 5.0.1
(MPL-2.0) and nlohmann/json 3.12.0 (MIT). Supported architectures: **WaveNet** (the trainer's
standard, lite, feather and nano sizes, and the 0.6/0.7 additions: bottlenecks, grouped
convolutions, gating and blending modes, per-layer activations, FiLM, head 1x1, a post-stack head
and a conditioning model), **LSTM**, **ConvNet** and **Linear**. Format versions 0.5.0 to 0.7.x
load. Slimmable WaveNets and the `SlimmableContainer` and `Sequential` containers are refused
with "Sedef can't load yet".

## 2. Signal flow

```
pedals ─► [ CaptureStage ] ─► cab, or a straight path ─► EQ ─► effects
             │
             ├─ ampSource = Model:   built-in AmpSection ─► delay to the stage latency
             └─ ampSource = Capture: input trim × interface calibration
                                     ─► RateBridge (host rate → model rate)
                                     ─► NAM model ─► clip ±36 dBFS, NaN → 0
                                     ─► RateBridge (model rate → host rate)
                                     ─► normalisation × output trim
```

Both paths share one latency, fixed per `prepare()`, so switching never moves the timing and the
dry/wet relationships downstream stay intact. Switching source is a 30 ms smoothstep crossfade;
loading another capture crossfades from the old model to the new one over the same time. When
no capture is loaded (or it is still loading, or missing) the stage plays the built-in amp.

## 3. Controls

| Parameter | Range | Meaning |
|---|---|---|
| `ampSource` | Model, Capture | what the amp section plays |
| `captureInput` | −24…+24 dB | gain into the model: drives it harder or softer, like the guitar's volume |
| `captureOutput` | −24…+24 dB | gain after the model |
| `captureCab` | on/off | "Capture Through Cab": off plays the capture straight into the EQ |
| `captureInterfaceLevel` | −10…+30 dBu | the player's interface: the analogue level that reads 0 dBFS; rig-wide, not stored in presets |

All five are appended to `ParameterList.inc` (ADR-0004) and smoothed (30 ms).

**Level.** Every capture is normalised once, when it is loaded: Sedef plays a 6 s reference
strum (the same signal the built-in amps are balanced with, `test::guitarStrum`, regenerated by
phasor rotation in `ReferenceStrum.cpp`) through the model at its own rate, measures the RMS
from 0.5 s on, and applies the gain that puts it at **−15 dBFS RMS**, where Lagoon, Reef and Abyss
sit at their defaults with the same strum. The gain is limited to ±40 dB; a model that measures
silent (below −120 dBFS), louder than +40 dBFS or non-finite is refused.

**Interface calibration.** A capture that records `input_level_dbu` (the interface level that
read 0 dBFS while capturing) gets its input scaled by `interfaceLevel / inputLevel`, in dB
`captureInterfaceLevel − input_level_dbu`, so a guitar hits it as hard as it hit the real amp.
The normalisation is measured with the reference interface at +12 dBu, so the default setting
plays a calibrated capture at the same level as an uncalibrated one. Captures without the field
ignore the setting, and the UI only shows it for captures that have it. `output_level_dbu` and
`loudness` are shown but not used: the reference-strum measurement replaces them.

**Cab.** `captureCab` defaults from the metadata's `gear_type` when the player loads a capture:
`amp_cab` and `amp_pedal_cab` turn it off; `amp`, `pedal_amp` and `preamp` turn it on; anything
else leaves it as it was. The straight path that replaces the cab has the cab's average gain at
the default rig, **+4.0 dB** (measured: +3.93 dB over the three amps), so a full-rig capture
lands next to the built-in amps through their cabs. It is a 30 ms crossfade, mono to both sides.

## 4. Untrusted files

Every file comes from somewhere else, so nothing in it reaches the core unchecked
(`CaptureValidation.cpp`). Before the core sees a byte:

- at most 24 MB, at most 2.5 M numbers and 64 levels of nesting (counted on the raw text before
  parsing);
- every field the core reads is present with the right type and range, including the ones it
  would read with `.at()` or assert on in release builds (shapes that would divide by zero or
  index out of bounds are refused);
- the weight count is computed from the config exactly as the core consumes it and must match;
  every weight is finite and within ±10⁶;
- cost limits: 2 M weights; 3 billion multiply-adds per second at the capture's own rate (a
  standard WaveNet needs 0.66 billion at 48 kHz, about 10 % of a core, and fits up to 192 kHz);
  2 billion to start, which is the receptive field times the multiply-adds per sample, run once
  by every instance before it plays; a receptive field of 2¹⁷ samples (2¹⁸ taps for Linear);
  32 MB of convolution history and weights; 512 channels, 8 layer arrays of 64 layers, kernels
  up to 64, dilations up to 32768, 16 LSTM layers;
- costs are counted as the core runs them: a grouped convolution keeps its full matrix (zeros
  between the groups) and multiplies all of it, so it costs what the ungrouped one does; only a
  depthwise one (groups = inputs = outputs) runs channel by channel;
- no matrix product takes more than 64 channels in or makes more than 512: Eigen packs larger
  ones into buffers it takes from the heap, on the audio thread (`EIGEN_STACK_ALLOCATION_LIMIT`
  is 128 KB, and 64 × 512 floats fill it exactly whatever the CPU's caches, since blocking only
  ever shrinks a dimension). Every trainer architecture uses at most 16 channels;
- a PReLU in a gated or blended layer has one slope per channel: the core applies those
  activations to every channel without wrapping around the slopes;
- model rates from 16 to 192 kHz (48 kHz when the file doesn't say);
- metadata strings are cut to 120 bytes of printable UTF-8; numbers outside sane ranges are
  dropped.

A conditioning model (`condition_dsp`) is validated the same way, one level deep, and the core
is handed the cleaned copy. It can't be a ConvNet: the core builds it itself, and its own ConvNet
allocates while it processes. A Linear one has an impulse response and a bias per output, as the
core reads it. Messages are sentences a player can act on: "The capture file is
damaged: …", "This capture is too large to play in real time: …", "This isn't a NAM capture: …".
The fuzz test corrupts a valid file 200 times and must never crash.

## 5. Real time

- **Build off the audio thread.** `CaptureFile::parse` validates, builds once and measures (about
  0.5 s of CPU for a standard WaveNet, on the plug-in's loader thread). `instantiate()` builds the
  runnable model for one chain with its rate bridge and buffers, then the core's `Reset()` sizes
  everything for 512-sample model blocks and prewarms it (about 6 ms).
- **Handover.** `CaptureStage::setModel` publishes the model; the audio thread picks it up at the
  start of a block and crossfades from the old one, which it retires into one of four slots it
  never frees. One fade runs at a time, so a model published during a fade plays once that fade
  is over (at most 30 ms). The collector (`setModel` itself, and the plug-in's 20 Hz timer) frees
  every retired model except the one still fading out, so the newest model always gets through,
  timer or not. `prepare()` and `reset()` end a fade at once: the model fading out was built for
  the old spec. The spec loader threads build for is written under a sequence count, so it is
  never read half-written. The audio thread never allocates or frees (`EngineTests`: "never
  allocates while captures play, switch and swap"; `CaptureStageTests`: no model is destroyed on
  the audio thread).
- **Input.** What reaches a model is cleaned first: non-finite samples become silence and
  anything beyond ±10⁶ (+120 dBFS) is clamped. A recurrent model would otherwise keep one NaN in
  its state for good; a model that is handed more frames than it was built for plays silence.
- **First block.** `instantiate()` also runs twice the latency of silence through the rate
  bridge, so a model that rests at an offset starts there instead of stepping up to it.
- **ConvNet.** The core's ConvNet allocates while it processes, so Sedef runs its own copy
  (`RtConvNet.cpp`) with the core's `Conv1D`, batch norm folded into a scale and offset, reading
  the weights in the same order. It matches the core sample for sample.
- **Settling.** A capture that has been bypassed is fed silence for its receptive field before it
  plays again, so it never replays the end of the last note.
- **Block sizes.** Host blocks of 1–4096 samples; the model always runs in its own chunks of at
  most 512.

## 6. Sample rate and latency

`RateBridge` converts between the host and the model with a windowed-sinc interpolator (Kaiser,
β = 8, about 80 dB of rejection, 1024 phases per zero crossing, 16 zero crossings, pass band 90 %
of the lower Nyquist). Positions are kept in exact integer time units (1/(f_host·f_model) s), so
the output doesn't depend on the block size, bit for bit. At equal rates it is a straight
pass-through.

The stage latency is the larger of the built-in amp's oversampler latency and what captures made
at 44.1, 48, 88.2 or 96 kHz need at that rate, so both sources share it, and how well a capture
plays never depends on the amp's latency or on which capture is loaded. What a capture needs
follows the rig's oversampling setting ([oversampling.md](oversampling.md)):

- **Low latency** (the default): the bridge uses the minimum-phase version of the same windowed
  sinc (`MinimumPhaseKernel`, from its real cepstrum): the same magnitude response with no
  look-ahead, so the delay is the filters' own group delay at low frequencies, 2.361 zero
  crossings per conversion, about 0.12 ms for the round trip at every host rate. The read
  position is set so the capture lags the stage's latency to half a sample at guitar
  frequencies.

  | Host rate | Built-in amp | Stage (both sources) | Added |
  |---|---|---|---|
  | 44.1 kHz | 5 | 5 | 0 |
  | 48 kHz | 5 | 6 | 1 sample, 0.02 ms |
  | 88.2 kHz | 3 | 10 | 7 samples, 0.08 ms |
  | 96 kHz | 3 | 11 | 8 samples, 0.08 ms |
  | 176.4 kHz | 0 | 21 | 0.12 ms |
  | 192 kHz | 0 | 23 | 0.12 ms |

  A capture made below 44.1 kHz needs more than that; it plays with the full filter, a little
  late (a 16 kHz capture at 48 kHz: 0.2 ms after the amp would).

- **Linear phase**: the bridge looks ahead by the full filter, as up to 0.4.0:

  | Host rate | Built-in amp | Stage (both sources) | Added |
  |---|---|---|---|
  | 44.1 kHz | 37 | 37 | 0 |
  | 48 kHz | 37 | 39 | 2 samples, 0.04 ms |
  | 88.2 kHz | 31 | 72 | 41 samples, 0.46 ms |
  | 96 kHz | 31 | 78 | 47 samples, 0.49 ms |
  | 176.4 kHz | 0 | 143 | 0.81 ms |
  | 192 kHz | 0 | 155 | 0.81 ms |

The latency is reported to the host through `Engine::latencySamples()`. In low latency every
capture gets the full 16-zero-crossing filter. In linear phase, captures made at 44.1 to
192 kHz get the full filter at every host rate; captures made at 16 to 32 kHz get 5 to 12. Budgeting for a 48 kHz capture only would leave a 44.1 kHz capture 15 zero
crossings at 48 kHz and 14 above, and none at all next to an amp without latency.

## 7. In the plug-in

- **Loading.** Load or Replace opens a file chooser for `.nam`; a file dropped on the panel is
  read by the page and sent over the bridge (at most 24 MB), validated, and kept under
  `<Sedef folder>/Captures/` (the same file again reuses its copy, a different one with the same
  name gets a number), so presets and the recent list can find it again. Loading runs on the
  library's worker; the newest request wins. A successful load sets `ampSource` to Capture and
  `captureCab` from the metadata.
- **Session state.** `getStateInformation` writes
  `<Capture name fileName path sha256 normalisationDb data>`, where `data` is the file itself,
  gzip-compressed and base64-encoded. A session therefore sounds the same on a machine that
  doesn't have the file. A standard WaveNet capture (407 KB) costs **177 KB** in the session.
  With the file embedded the restore is synchronous (the capture plays from the first block) and,
  when the file's SHA-256 matches, uses the stored level instead of measuring again: about 17 ms
  instead of 0.5 s. The worker measures it afterwards; a stored level more than 0.5 dB off (a
  damaged or crafted session) is replaced by the measured one. A state without the file, or with
  a damaged one, is looked up on disk on the worker, never on the thread restoring the state.
  Load-then-save reproduces the state byte for byte, also while the capture is missing or still
  being looked for.
- **Paths** from sessions, presets and the recent list must be absolute (a relative one would
  mean whatever the host's working folder holds) and name a regular file: links are followed,
  pipes and devices are refused without waiting on them, and a file is read once, at most 24 MB
  of it, so what was hashed is what loads. A dropped file whose name Windows keeps for a device
  (CON, NUL, COM1 …, whatever follows the first dot) is kept with a leading underscore.
- **Presets** keep a reference only, `"capture": { name, fileName, path, sha256 }`, and only when
  the preset plays a capture: a preset is a small file people share, and a capture can be tens
  of megabytes and may not be theirs to share. Loading a preset finds the capture by, in order:
  one already built this session (by hash, instantly), the path, the recent list by hash, a kept
  dropped copy. Snapshots, A/B and undo carry the exact capture. A different capture makes the
  preset dirty; a missing one does not.
- **Missing.** When nothing matches, the stage plays the built-in amp and the panel names the
  missing file and where it was, with a Locate button. The session keeps the reference, so saving
  doesn't lose it.
- **Recent list.** The last 12 captures loaded, shared by every instance (`captures.json` next to
  the presets, behind an inter-process lock); files that no longer exist are not shown.
- **Bridge.** `sedef_capture_load`, `sedef_capture_loadData(fileName, text)`,
  `sedef_capture_loadRecent(path)` (only paths the recent list offers), `sedef_capture_clear`,
  the `sedef:capture` event and `capture` in the handshake (`ui/src/bridge/protocol.ts`). The
  additions are backwards compatible, so the protocol version stays 2; a UI talking to an older
  plug-in hides captures.
- **Finding captures.** The empty panel links to [TONE3000](https://www.tone3000.com), the
  community library of NAM captures, through `sedef_openUrl` (HTTPS only). Sedef ships no
  captures.

## 8. CPU

Apple M2, Release build, one chain (`CaptureBench.cpp`, `[.bench]`):

| Capture | Host rate | Block | Time per sample | One core |
|---|---|---|---|---|
| standard WaveNet (13,802 weights) | 48 kHz | 256 | 2.1 µs | 10.2 % |
| standard WaveNet | 48 kHz | 64 | 2.4 µs | 11.6 % |
| standard WaveNet | 44.1 kHz (bridged) | 256 | 2.6 µs | 11.3 % |
| standard WaveNet | 96 kHz (bridged) | 256 | 1.1 µs | 10.3 % |
| built-in Reef, for comparison | 48 kHz | 256 | 0.19 µs | 0.9 % |

The model runs at its own rate, so the cost per second is the same at every host rate. Dual
amp mode builds one instance per chain and costs twice as much.

  every architecture; calibration shifts the level by the interface difference; a known level
  skips the measurement and plays bit for bit the same; a conditioned WaveNet counts each array's

  gated or blended layer; grouped convolutions counted at their real cost; the per-second and
  start caps; products wider than Eigen's stack buffers (and that the allowed ones fit, from
  Eigen's own blocking); a ConvNet as the conditioning model.

- **Plug-in** (`CaptureLibraryTests.cpp`): metadata, damaged files, a byte-exact session round

## 11. Limitations

- Slimmable WaveNets and the container architectures don't load yet.
- The stage latency rises by 2 samples at 48 kHz and by 0.46–0.81 ms at 88.2 kHz and above for
  everyone, not only while a capture plays (table above), because the host can't be told about a
  latency change cleanly mid-session.
- The no-allocation tests count `operator new`; Eigen takes its buffers with `malloc`, which they
  don't see. The product-size limit (section 4) is what keeps Eigen off the heap, and a test
  checks it against Eigen's blocking.
- The level is matched with one strum. Captures compress differently from the built-in amps, so
  with other playing they can sit a few dB apart: with `tools/sedef-render`'s DI, the core's
  example standard WaveNet renders at −11.7 dBFS through the cab, next to Lagoon −17.2, Reef
  −16.0 and Abyss −11.5.
- The EQ bank and the "cab follows amp" link keep following the built-in amp selection while a
  capture plays.
- Dropping a file onto the editor is tested against the browser preview; inside a host it
  depends on the WebView passing file drops to the page.
- The preset browser still shows a preset's built-in amp, not its capture.
