# UX pass, November 2026 (0.9.0)

A review of the whole Sedef Amp editor and Sedef MIDI's window for 0.9.0, with the findings
ranked by what they cost a player, what was fixed and what was left. No new audio features, no
parameter or engine changes; the palette, type, density and artwork are as they were.

## How

- **Every view rendered** in headless Chromium against the mock (`pnpm screenshots` plus a
  scratch script for states the docs images don't show: Save as, a removed pedal's notice, an
  empty board, the tuner with nothing playing, Capture with nothing loaded, an update error,
  the plug-in header, the window at 75 %, all sixteen pedals at 75 %), each one looked at.
- **A cross-discipline review** (the `better-interface` method: accessibility, layout, writing,
  typography, colour, UI polish, in that order), with an accessibility walk in the browser:
  the accessibility tree of each section and overlay searched for unnamed controls (none), and
  a Tab walk through each recording every stop's name, size and focus ring.
- **The first five minutes of a new player** in the standalone app, below.

## The first five minutes

| Step | What the player meets | Where they stop and think |
| --- | --- | --- |
| Open the app | The amp page on Glassy Chorus. JUCE mutes a standalone app's input until it is switched on, and says so in a grey bar above the window. | Nothing in Sedef's own window leads to the audio device; the way there is the title bar's Options button. |
| Get sound in | The input meter, a 92 px bar. | With the input muted or the wrong channel picked the bar stays empty and nothing says why. The tuner says "Play a string". |
| Set the level | The same bar: no numbers, no target. | Where should it land? The bar turns amber, the app's warning colour, at −3 dBFS, right where the presets want a hard strum (−4 to −2 dBFS, [amps.md](../dsp/amps.md#input-level-what-dbfs-means-here)). A player who gets it right is told to back off. |
| Pick a sound | The preset bar and browser. | Nothing: audition with the arrows, Enter keeps, Esc goes back, and the strip says so. |
| Tweak it | Knobs with values; the amp cards. | The cards' descriptions end in "…" at every window size. |
| Save it | Save (⌘S), Save as for a factory preset. | Nothing. |

## Findings

Ranked by severity, then by reach. "Fixed" rows have before and after screenshots.

## What feels different

- The input meter has a target, and a chip under it tells you in words whether your level is
  right. Click it for what to turn.
- The standalone app opens its audio device window from Settings or from that panel.
- If nothing is coming in, Sedef says so, in the header and in the tuner.
- T opens the tuner.
- The amp cards read in full, the header's panels no longer cover the Doubler switch, the
  metronome says how to edit its beats.

## Left, and why

- **A global shortcut list.** It stays in the preset browser, where most keys apply. A second
  copy in Settings would make that panel taller than the window at 75 %; `?` is free if a
  later pass wants an overlay.
- **Unmuting the standalone app's input by default.** Sedef MIDI does it because its audio is
  muted; Sedef Amp plays its input through the speakers, and JUCE's default protects a laptop
  from howling feedback. The No signal state and Audio settings… cover the cost.
- **The output level.** The output meter keeps its amber near 0 dBFS, which is right there.
  The output level depends on the host or the interface after Sedef, so there is no target to
  draw.
- Rows 12–15 above.

## Verification

- `pnpm test` (43 files, 392 tests at the time of writing), `pnpm typecheck`, `pnpm lint`,
  `pnpm format:check`.
- The input level verdict: `features/header/inputLevel.test.ts` (each state, the windows, the
  hold, the Input knob, hysteresis, silence) and `InputLevelChip.test.tsx` (names, panel text
  per state, standalone and plug-in, the tuner's Check input, T, the clip lamp's name).
- Screenshots: every docs image re-rendered (the header changed in all of them), plus
  `input-level.png`; each one looked at.
- The plug-in: `SedefAmp_Standalone` and `SedefAmp_VST3` built locally with
  `SEDEF_WARNINGS_AS_ERRORS=ON` (Apple clang); CI builds the rest. The standalone app was not
  launched (no GUI on the build machine), so `sedef_audioSettings` opening JUCE's window is
  checked by the same code path in Sedef MIDI, not by running it.
